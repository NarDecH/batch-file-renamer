🗓️Timeline

v0.12.0 — baseline

First version whose updater (signed install + auto-update) was exercised on a real user machine — which immediately surfaced two unverified integration points: the WebView2 dialog chain and the NSIS update path.

v0.12.1 — preview table rendered empty

Backend log clearly had preview results, but the DOM showed nothing. Cause: Svelte 5 runes — a top-level let stops being reactive; every reactive variable must be $state. Also registered the missing clear_entries command (Clear button worked in the frontend but had no backend command attached).

v0.12.2 — silent dialogs (the security-critical one)

Current WebView2 runtimes auto-accept window.confirm() without showing anything. Proven on both dev and the built installer: pressing "Clear list", "Remove selected" or "Rename" destroyed data with no confirmation at all. Fix: every confirmation moved to native plugin-dialog (ask() / message()) — real task dialogs. Also added a non-blocking notice banner (coloured, close button, auto-dismiss after 8s) and wired an E2E UIA step into the CI release job (ops/e2e.ps1: click Clear on the real built window, dialog appears, list empties only after Yes).

v0.12.3 — NSIS update hang on a hidden wizard page

The in-app "Install & restart" stalled: the updater's default install mode is passive (/P), and the Tauri NSIS template has a PageReinstall ("Already Installed") page that appears as a hidden modal and hangs the flow. Fix in tauri.conf.json: plugins.updater.windows.installMode = "quiet" (NSIS runs /S — the wizard pages are always skipped) and nsis.installMode = "currentUser" (same per-user install, no UAC). Proven on the real machine: one click → fully silent install in ~36s → app relaunches itself, log records GUI starting (v0.12.3), registry DisplayVersion = 0.12.3. Plus a new watchdog: after 90s of a pending install the app logs it and shows a banner telling the user the install appears stuck and to install directly from the setup file, instead of waiting silently forever.
